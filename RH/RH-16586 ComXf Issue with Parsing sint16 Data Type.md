## 描述

Hi， 

 The customer encountered a serialization issue while using the ComXf module with  **RTA-CAR 12.11.0VCTCESR1pr1**. 

 **Issue Description:** 

The signal that is causing the issue is highlighted in the red box in the figure below, . 

![[RH-16586-image001.png]] 

2、The  **BaseType** of the  **ISignal** in the system description is  **uint16**. 

![[RH-16586-image005.png]] 

3、The signal is defined within a  **Signal Group**. The  **Signal Group** is mapped to the corresponding  **Port**, and the data prototype in the corresponding  **Interface** of that  **Port** is of type sint16. 

![[RH-16586-image006.png]] 

4、For this signal, the code generated by CodeGen uses the serialization code highlighted in the red box in the figure below: 

![[RH-16586-image002.png]] 

![[RH-16586-image003.png]] 

![[RH-16586-image004.png]] 

5、This serialization approach has two issues: 

- First, it directly copies a  **uint16** value into an  **sint16** buffer through memory copying. Since*
   ***uint16** and  **sint16** have different data representations, this can lead to incorrect data interpretation.
- Second, the value ranges of  **uint16** and  **sint16** are different. The range of  **uint16** is  **0 to 65535**, while the range of  **sint16** is  **-32768 to 32767**. If the value exceeds  **32767** (for example,  **32999**), it will be interpreted as a negative  **sint16** value, resulting in a loss of data accuracy.

 **Expected Outcome:** 

The customer hopes that we can resolve this issue. Could you please help analyze it? Thank you!
