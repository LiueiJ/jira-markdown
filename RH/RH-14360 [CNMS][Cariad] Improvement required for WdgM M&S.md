## 描述

Dear Marc,

Customer: Cariad

Toolchain: RTA-CAR12.7.0

The WdgM Master & Satellite configuration scenario (row1) is like below:

 1
 Core
 Core0
 Core1
 Core2

 SysCore
 AppCore
 CanCore

 2
 Init Event
 I_WdgM_Init_Master
 I_WdgM_Init_Satellite_AppCore
 I_WdgM_Init_Satellite_CanCore

 3
 Init Func
 WdgM_Init_Master
 WdgM_Init_Satellite_AppCore
 WdgM_Init_Satellite_CanCore

 4
 Init Task
 OsTask_SysOsApp_Startup2
 OsTask_AppOsApp_Startup
 OsTask_CanOsApp_Startup

After configuring, the init events and init runnables are generated like row2 and row3 in SWCD arxml.

- WdgM_SysOsApp_Cfg_SWCD.arxml
- WdgM_AppOsApp_Cfg_SWCD.arxml
- WdgM_CanOsApp_Cfg_SWCD.arxml

Then we must map those init events to task otherwise RTE generation report error, like row4.

![[RH-14360-image001.png]]

But there is a limitation or intended design that satellite init functions must be called after master init function, otherwise satellite init will be failed as code is designed this way:

![[RH-14360-image002.png]]

So we must make sure calling TASK(OsTask_SysOsApp_Startup2) after calling TASK(OsTask_AppOsApp_Startup) or TASK(OsTask_CanOsApp_Startup).

How can we make sure of it?

1. Chain task method, OsTask_SysOsApp_Startup2 -> OsTask_AppOsApp_Startup -> OsTask_CanOsApp_Startup, but the other startup functions from Core1 and Core2 may be delayed. This method is not good enough.

![[RH-14360-image003.png]]

- Or we add one init event “MasterTriggerSatelliteInit” which is generated from Master SWCD, then we can implement the integration code “WdgM_Call_Init_Satellite” as want. I think this one is better, but the init event and runnable is missing not generated by WdgM_SysOsApp_Cfg_SWCD.arxml. How do you think, can we push product team to optimize the design? Thanks.

![[RH-14360-image004.png]]

> According to the Multi-Partition WdgM design, the Master initialization should be called before the Satellite initialization, since the Master is responsible for taking action in case of a Supervision failure.
>
> Of the two proposed solutions above, triggering the Satellite initialization through a "MasterTriggerSatelliteInit" event appears to be the better option. However, if the Memory Protection Unit is enabled, ensure that this approach does not violate cross-partition access restrictions or FFI.
