# RH-15143 MemAcc Module Usage Issue in the Cariad Project

> [!jira] Closed · High · [[Dong_LIU|Dong LIU]] · 更新于 2026-04-29T11:37:36.000+0200
> [在 Jira 中打开](https://rtahotline.etas.com/jira/browse/RH-15143)

## 描述

Hi，

We have encountered an issue with the MemAcc module in Cariad project. We would appreciate your support in reviewing this issue. Thank you.

**Project Configuration Overview:**

The customer is using the Infineon TC489 chip. The RTACAR MemAcc module is used together with Infineon’s Mem module.

The customer needs to access both DFLASH and PFLASH through MemAcc. However, Infineon’s Mem module only supports configuring DFLASH and PFLASH as two separate MemInstances. Therefore, RTACAR MemAcc also has to be configured with two MemInstances.

**Problem Description:**

The two MemInstances generated by the RTACAR tool belong to two different Devices. According to the generated code, these two Devices access memory independently, as shown in the figure below.

![[RH-15143-image001.png]]

![[RH-15143-image002.png]]

According to Infineon’s chip manual, DFLASH and PFLASH on the TC489 are mutually exclusive in terms of access, as highlighted in the figure below. The customer has also confirmed this point with Infineon’s FAE.

![[RH-15143-image003.png]]

**Customer Request:**

The customer would like the two MemInstances generated by RTACAR to either:

- belong to the same Device, or
- belong to two different Devices but with a mechanism that ensures mutually exclusive access to DFlash and PFlash.

Do we have any solution for this?

Thank you!!!
