## 描述

Hi，

The customer encountered a serialization issue while using the ComXf module with **RTA-CAR 12.11.0VCTCESR1pr1**.

**Issue 1:**

**Issue Description:**

1.The signal that is causing the issue is highlighted in the red box in the figure below.

![[RH-16581-image001.png]]

2.The **BaseType** of the **ISignal** in the system description is **uint16**.

![[RH-16581-image002.png]]

3.The signal is defined within a **Signal Group**. The **Signal Group** is mapped to the corresponding **Port**, and the data prototype in the corresponding **Interface** of that **Port** is of type **float32**.

![[RH-16581-image003.png]]

4.The code generated by CodeGen uses the following macro, highlighted in the red box:

COMXF_PRV_READ_MSBF_T2_A1((*dataElement).IDTElement_P_ECM_LZCU_EngAbgasT_P_ECM_LZCU_100_2, 3u);

![[RH-16581-image006.png]]

![[RH-16581-image005.png]]

![[RH-16581-image004.png]]

5.This approach directly copies a **uint16** value into a **float32** variable through memory reinterpretation, which causes incorrect data conversion and has led to engine operation issues on the customer's side.

For example, CANoe sends the following raw signal data:

0x00 0x00 0x0F 0xA0

which represents a physical value of **1000**. However, the generated code reinterprets these four bytes directly as a **float32** value, resulting in an extremely small floating-point number instead of the expected value of **1000**.

 

**Issue 2:**

**Issue Description:**

This issue is similar to issue 1, the Port's data type is sint16.

1.The signal that is causing the issue is highlighted in the red box in the figure below, .

![[RH-16581-image001.png]]

2.The **BaseType** of the **ISignal** in the system description is **uint16**.

![[RH-16581-image005.png]]

3.The signal is defined within a **Signal Group**. The **Signal Group** is mapped to the corresponding **Port**, and the data prototype in the corresponding **Interface** of that **Port** is of type sint16.

![[RH-16581-image006.png]]

4.For this signal, the code generated by CodeGen uses the serialization code highlighted in the red box in the figure below:

![[RH-16581-image002.png]]

![[RH-16581-image003.png]]

![[RH-16581-image004.png]]

5.This serialization approach has two issues:

- First, it directly copies a **uint16** value into an **sint16** buffer through memory copying. Since*
  **{**}uint16{**} and *sint16** have different data representations, this can lead to incorrect data interpretation.
- Second, the value ranges of **uint16** and **sint16** are different. The range of **uint16** is **0 to 65535**, while the range of **sint16** is **-32768 to 32767**. If the value exceeds **32767** (for example, **32999**), it will be interpreted as a negative **sint16** value, resulting in a loss of data accuracy.

**Expected Behavior:**

The customer hopes that we can resolve this issue. Could you please help analyze it? Thank you!
